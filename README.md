# Космос как инфраструктура — решение команды

КосмоХакатон 2026, федеральный проект «Кадры для космоса». Кейс АНО
«Исследовательский центр «Космическая экономика и политика»: выбрать портфель
из четырёх космических сервисов общего пользования при ограниченном бюджете,
обосновать экономическую модель и проверить портфель в базовом и
стресс-сценарии.

Репозиторий содержит управленческую записку, работающий расчётный инструмент с
исходным кодом и материалы для воспроизведения всех приведённых чисел.

## Рекомендуемый портфель

**FIRE:D3 + AGRI:C + TRANS:C + ENV:D3** — мониторинг лесных пожаров Сибири и
экологический мониторинг Волжско-Каспийского бассейна в режиме совместной
закупки D3 с сохранённым общественным ядром; агроаналитика Юга и транспортный
мониторинг Центра в коммерческом режиме C.

| Показатель | Значение | Порог кейса |
|---|---:|---|
| C0 (разово) | 1104 млн руб. | ≤ 1300 BASE / ≤ 1180 STRESS |
| OPEX | 300.55 млн руб./год | ≤ 360 |
| VPUB | 1199 млн руб./год | ≥ 1000 |
| kcash | 1.32 | ≥ 0.6 |
| NPV (r = 10 %, T = 10 лет) | −505 млн руб. | — |
| SROI | 2.50 | — |

Портфель допустим в обоих сценариях **без пересмотра состава**: запас до
стрессового лимита 76 млн руб. Отрицательный NPV — не дефект расчёта, а
структурное свойство всех 1056 допустимых портфелей кейса; обоснование и
управленческий вывод — в записке, раздел П3.

## Быстрый старт

```bash
cd test-main
pip install pandas numpy
python tests.py                                  # 12 контрольных примеров -> 12/12
python evaluate.py FIRE:D3 AGRI:C TRANS:C ENV:D3 # пересчёт портфеля записки
```

Python 3.9+, только `pandas` и `numpy`. Внешних API, ключей, регистрации и
оплаты не требуется, всё работает офлайн.

## Где расчётная логика

Модель разделена на два слоя, и это разделение принципиально.

**Канонический слой** — [`test-main/case_core.py`](test-main/case_core.py),
файл организаторов, не изменён ни одной строкой. Содержит формулы применения
режима к лоту, агрегацию портфеля и девять формальных ограничений.

**Слой команды** — [`test-main/team_model.py`](test-main/team_model.py),
надстройка поверх канонического:

| Раздел модуля | Содержание |
|---|---|
| 1–3 | веса, нормировка к порогам, отчёт по ограничениям с запасом |
| 4–5 | детализация портфеля, удельные показатели, диверсификация |
| 6 | финансовые метрики: NPV, IRR, окупаемость, PI, ROI, SROI |
| 7 | полный расчёт одного портфеля |
| 8 | перебор и поиск оптимума |
| 9 | реестр критериев, блочные fitness-функции, фронт Парето |

Допущения команды, которых нет в исходных данных кейса (ставка дисконтирования
10 %, горизонт 10 лет), собраны в словаре `ASSUMPTIONS` в начале модуля и
передаются явно. Коэффициенты пользовательских режимов выводятся формулами из
канонических A и B в [`test-main/user_modes.py`](test-main/user_modes.py).

## Как проверить

| Критерий | Команда | Что покажет |
|---|---|---|
| Т1 корректность | `python tests.py` | 12 примеров, включая сверку быстрого пути перебора с каноническим `case_core` на **всех 5670** комбинациях A/B/C |
| Т2 смена параметров | `python evaluate.py FLOOD:A AGRI:C TRANS:B ENV:A` | любой состав, режимы, веса, ставка и горизонт — аргументами, без правки кода |
| Т3 ограничения | `python evaluate.py ARCTIC:A SSA:A FIRE:A FLOOD:A --constraints-only` | порог, факт, запас и PASS/FAIL по каждому из девяти ограничений; здесь видно конкретное нарушение |
| Т4 сценарии | `python evaluate.py FIRE:D3 AGRI:C TRANS:C ENV:D3` | блок «Сравнение сценариев»: BASE и STRESS рядом |
| Т5 воспроизводимость | [`test-main/RUN.md`](test-main/RUN.md) | полный цикл: тесты, демо, перебор, отчёт |

Полный перебор с пересборкой отчётов:

```bash
python pareto_search.py --verify   # перебор + сверка с каноническим слоем
python pareto_report.py            # пересобирает PARETO_FRONT.md и output/
```

Все числа записки воспроизводятся этими командами.
